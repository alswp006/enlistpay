# Architecture Review
Generated: 2026-09-07T15:48:44.300Z
Score: 74/100

## Summary
The codebase has a clean, well-documented layered architecture (domain/ for pure logic, storage/ for persistence, components/ for pre-built UI primitives, single AppDataProvider context for state) with no circular dependencies detected. However, there is notable small-scale duplication of helper logic (haptic firing, chip test-bridges, sorting, default flags) that was never consolidated into the shared hooks/utils that already exist for that purpose, plus a parallel/overlapping storage abstraction and several likely-unused exports.

## Issues

- [consistency] Two parallel storage access patterns coexist: AppDataProvider calls synchronous functions directly (loadProfile/saveProfile/loadFlags/loadVacations), while storage/*.ts also expose an async 'contract-mandated' API (getProfile, addVacationRecord, getVacationRecords, storageGet/storageSet) that isn't used by the actual app state layer shown.
